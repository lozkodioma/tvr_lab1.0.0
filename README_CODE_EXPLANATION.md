## 2. ПОЯСНЕННЯ HTML-РОЗМІТКИ (`index.html`)

1. **Семантика сторінки:**
   - `<header>` — назва застосунку, лічильник контактів `#totalBadge` та кнопка зміни теми `#themeBtn`.
   - `<main>` — основний вміст, що містить:
     - `<section class="form-section">` — форма додавання контакту;
     - `<section class="controls-section">` — інпути пошуку, фільтрації та сортування;
     - `<section class="contacts-section">` — порожній контейнер `#contactsContainer`, куди JavaScript вставляє згенеровані контакти.
   - `<footer>` — підвал з інформацією про роботу та виконавця.
2. **Атрибут `novalidate` у формі:**
   - Вимикає стандартні браузерні спливаючі повідомлення, щоб ми могли повністю контролювати виведення помилок через наш JavaScript та стилізувати поля червоною рамкою.
3. **Модальне вікно (`#editModal`):**
   - Має атрибут `hidden` за замовчуванням.
   - Складається з напівпрозорої підложки `.modal-overlay` та білого вікна форми `.modal-content`.
   - Відображається простим видаленням атрибута: `editModal.hidden = false`.

## 3. ПОЯСНЕННЯ СТИЛІВ (`styles.css`)

1. **Світла та темна теми (CSS Variables):**
   - У `:root` оголошено кольори для світлої теми: `--bg-page: #f8fafc`, `--bg-card: #ffffff`, `--text: #0f172a`.
   - У селекторі `[data-theme="dark"]` ці ж змінні перевизначаються темними відтінками: `--bg-page: #0f172a`, `--bg-card: #1e293b`, `--text: #f8fafc`.
   - Завдяки цьому при перемиканні теми змінюється лише один атрибут у тегу `<html>`, а всі кольори оновлюються автоматично.
2. **Адаптивні сітки:**
   - Поля форми використовують `grid-template-columns: repeat(auto-fit, minmax(200px, 1fr))`. Це означає: поля автоматично займають потрібну кількість колонок і переносяться на новий рядок на смартфонах.
   - Картки контактів використовують `grid-template-columns: repeat(auto-fill, minmax(280px, 1fr))` — автоматично формують зручну сітку карток.
3. **Стан помилки:**
   - Клас `input.invalid` робить рамку червоною (`--danger`), а під інпутом з'являється текст повідомлення `.error-msg`.

## 4. ДЕТАЛЬНИЙ РОЗБІР JAVASCRIPT (`app.js`)

Код структурований зверху вниз за 5 логічними блоками:

### Блок 1. Моделі даних (Класи `Contact` та `ContactManager`)
```javascript
class Contact {
    constructor(id, name, phone, email = "", category = "Родина", notes = "", createdAt = new Date().toISOString()) {
        this.id = id || String(Date.now()); // унікальний ID за часом
        this.name = name.trim();
        this.phone = phone.trim();
        this.email = email.trim(); // опціональний
        this.category = category;
        this.notes = notes.trim();
        this.createdAt = createdAt;
    }
}
```
- Якщо `id` не передано (новий запис), генерується `Date.now()`.
- Усі рядки очищуються від пробілів методом `.trim()`.

```javascript
class ContactManager { ... }
```
Клас інкапсулює масив `this.contacts`:
- `add(data)`: створює новий `Contact` і додає його на початок масиву (`unshift`). Зберігає стан у `localStorage`.
- `update(id, data)`: знаходить контакт через `find` та оновлює його поля.
- `remove(id)`: фільтрує масив, залишаючи всі контакти, крім видаленого (`filter`).
- `getById(id)`: знаходить об'єкт за його ідентифікатором.
- `search(query, list)`: нечутливий до регістру пошук за іменем або номером телефону через `toLowerCase()` та `includes()`.
- `filter(category, list)`: повертає контакти обраної категорії.
- `sort(by, list)`: сортує масив. Якщо обрано `"category"`, впорядковує контакти спочатку за групами («Родина» -> «Робота» -> «Друзі»), а всередині груп — за алфавітом. Для імен використовується `localeCompare(..., "uk")`, щоб правильно враховувати українські літери («І», «Ї», «Є»). Якщо обрано сортування за ім'ям або датою, сортування працює наскрізно через усі категорії.
- `groupBy(list)`: повертає об'єкт виду `{ "Родина": [...], "Робота": [...], "Друзі": [...] }`.
- `save()` та `load()`: серіалізація через `JSON.stringify` та відновлення через `JSON.parse`. Якщо сховище порожнє, автоматично створюються 3 демонстраційні контакти.

### Блок 2. Регулярні вирази та функції валідації
```javascript
const nameRegex = /^[a-zA-Zа-яА-ЯіІїЇєЄґҐ\s'-]{2,50}$/;
const phoneRegex = /^(\+?380|0)\d{9}$/;
const emailRegex = /^[^\s@]+@[^\s@]+\.[^\s@]+$/;
```
1. **Ім'я (`nameRegex`):**
   - Дозволяє українські та англійські літери, пробіли, дефіси та апострофи.
   - **Дозволяє як одне слово («Тарас»), так і декілька слів («Тарас Григорович Шевченко»).**
   - Довжина: від 2 до 50 символів.
2. **Телефон (`phoneRegex`):**
   - Дозволяє формати: `+380XXXXXXXXX` або `0XXXXXXXXX` (рівно 9 цифр після коду).
3. **Email (`validateEmail`):**
   - Якщо значення порожнє (`if (!val) return "";`), функція повертає порожній рядок — **поле не є обов'язковим**, помилки немає.
   - Якщо користувач ввів текст, він перевіряється шаблоном `emailRegex` (має бути `@` та домен).

### Блок 3. Відображення в DOM (`render`)
Функція `render()` виконується після кожної зміни даних:
1. Отримує пошуковий запит, категорію фільтрації та тип сортування.
2. Очищує список: `contactsContainer.innerHTML = ""`.
3. Оновлює лічильник `totalBadge`.
4. Якщо список порожній — знімає `hidden` з напису «Контактів не знайдено».
5. Групує контакти за категоріями через `manager.groupBy(list)`.
6. Для кожної категорії створює блок із заголовком та картками.
7. Кожна картка зберігає `data-id="ідентифікатор"`. Вміст екранується через `escapeHtml()`, що повністю захищає сторінку від XSS-ін'єкцій.

### Блок 4. Обробка подій та Делегування
1. **Подія `submit` форми:**
   - `e.preventDefault()` скасовує перезавантаження сторінки.
   - Викликаються перевірки полів. Якщо є помилки, додається клас `invalid` та виводиться текст помилки.
   - Якщо все валідно — викликається `manager.add(...)`, форма очищується, викликається `render()`.
2. **Делегування подій на списку (`contactsContainer.addEventListener("click")`):**
   - Слухач встановлено **один раз на спільний контейнер**, а не на кожну кнопку.
   - Метод `e.target.closest(".btn-del")` визначає, чи клікнули на кнопку видалення.
   - Якщо так — виводиться браузерне підтвердження `confirm("Видалити контакт?")`. При згоді контакт видаляється, а список перемальовується.
   - Якщо клікнули на `.btn-edit` — відкривається модальне вікно, у поля якого записуються поточні дані контакту.

## 5. ШПАРГАЛКА ДЛЯ ЗАХИСТУ: ВІДПОВІДІ НА ПИТАННЯ ВИКЛАДАЧА

| Питання викладача | Коротка та впевнена відповідь |
| :--- | :--- |
| **Чому для видалення використано делегування?** | Оскільки картки створюються динамічно, вішати обробник на кожну окрему кнопку неефективно. Ми вішаємо один слухач на спільний контейнер і ловимо подію через спливання (Event Bubbling) за допомогою `e.target.closest()`. |
| **Чи обов'язковий email і скільки слів може бути в імені?** | Email необов'язковий — якщо поле порожнє, валідація проходить успішно. Ім'я може містити як одне слово (наприклад, «Тарас»), так і кілька слів (ПІБ), оскільки регулярний вираз дозволяє літери та пробіли. |
| **Де зберігаються контакти та тема?** | У браузерному сховищі `localStorage` під ключами `contacts_list` (JSON-рядок із масивом об'єктів) та `app_theme` (рядок `'light'` або `'dark'`). |
| **Навіщо потрібен `event.preventDefault()`?** | Щоб скасувати стандартну поведінку форми — надсилання HTTP-запиту з перезавантаженням сторінки, і обробити дані локально в JavaScript. |
| **Яке додаткове завдання реалізовано?** | Додатковий варіант 2 — «Теми оформлення (Light / Dark mode)». Реалізовано перемикання через CSS Custom Properties та збереження обраної теми в `localStorage`. |
