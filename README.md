## 1. МЕТА РОБОТИ

Закріплення практичних навичок семантичної верстки веб-сторінок засобами HTML5, формування вмінь створення адаптивних макетів інтерфейсу за допомогою технологій CSS3 (Flexbox та Grid Layout), отримання базових навичок об'єктно-орієнтованого програмування мовою JavaScript ES6+ (створення класів, моделювання сутностей предметної області та реалізація логіки управління колекцією об'єктів), а також набуття практичних навичок динамічної модифікації вмісту сторінки засобами DOM та обробки подій користувача. 

Окремим завданням є використання регулярних виразів (RegExp) для клієнтської валідації даних форми, збереження стану застосунку на стороні клієнта за допомогою `localStorage` у форматі JSON та реалізація додаткового завдання на підвищену оцінку (перемикання тем оформлення).

### 3.3. Моделі даних ES6+ (`app.js`)
Для представлення предметної області створено клас сутності `Contact` та клас-менеджер `ContactManager`, що інкапсулює масив контактів і синхронізацію з `localStorage`:

```javascript
class Contact {
    constructor(id, name, phone, email = "", category = "Родина", notes = "", createdAt = new Date().toISOString()) {
        this.id = id || String(Date.now());
        this.name = name.trim();
        this.phone = phone.trim();
        this.email = email.trim();
        this.category = category;
        this.notes = notes.trim();
        this.createdAt = createdAt;
    }
}

class ContactManager {
    constructor(key = "contacts_list") {
        this.key = key;
        this.contacts = this.load();
    }
    save() {
        localStorage.setItem(this.key, JSON.stringify(this.contacts));
    }
    load() {
        const raw = localStorage.getItem(this.key);
        return raw ? JSON.parse(raw) : this.getDefaults();
    }
}
```

### 3.4. Валідація даних форми за допомогою регулярних виразів
Перевірка полів здійснюється функціями валідації. Ім'я допускає одне або кілька слів, телефон перевіряє формат операторів України, а email перевіряється лише за умови наявності введеного тексту:

```javascript
const nameRegex = /^[a-zA-Zа-яА-ЯіІїЇєЄґҐ0-9\s'-]{2,50}$/;
const phoneRegex = /^(\+?380|0)\d{9}$/;
const emailRegex = /^[^\s@]+@[^\s@]+\.[^\s@]+$/;

function validateName(val) {
    const trimmed = val.trim();
    if (!trimmed) return "Введіть ім'я";
    if (!nameRegex.test(trimmed)) return "Ім'я має містити від 2 символів (літери, цифри, дефіс)";
    return "";
}

function validateEmail(val) {
    const trimmed = val.trim();
    if (!trimmed) return ""; // Поле є необов'язковим
    return emailRegex.test(trimmed) ? "" : "Некоректний формат email";
}
```

### 3.5. Динамічне формування списку (DOM) та групування
Функція `render` очищує контейнер, групує контакти за категоріями («Родина», «Робота», «Друзі») та динамічно генерує картки із збереженням ідентифікатора у `dataset.id`:

```javascript
function createCard(c) {
    const card = document.createElement("article");
    card.className = "contact-card";
    card.dataset.id = c.id;
    card.innerHTML = `
        <div class="card-header">
            <h4>${escapeHtml(c.name)}</h4>
            <span class="cat-badge cat-${c.category.toLowerCase()}">${c.category}</span>
        </div>
        <div class="card-info">
            <span>📞 <a href="tel:${escapeHtml(c.phone)}">${escapeHtml(c.phone)}</a></span>
            ${c.email ? `<span>✉️ <a href="mailto:${escapeHtml(c.email)}">${escapeHtml(c.email)}</a></span>` : ""}
        </div>
        <div class="card-btns">
            <button type="button" class="btn btn-outline btn-sm btn-edit">Редагувати</button>
            <button type="button" class="btn btn-danger btn-sm btn-del">Видалити</button>
        </div>
    `;
    return card;
}
```

### 3.6. Обробка подій та делегування
Для оптимізації продуктивності та роботи з динамічно створеними елементами слухач події `click` встановлено на батьківський контейнер. Визначення цільової кнопки виконується методом `event.target.closest()`:

```javascript
// Скасування перезавантаження сторінки при відправці форми
contactForm.addEventListener("submit", (e) => {
    e.preventDefault();
    // Виклик валідації полів та збереження нового контакту
});

// Делегування подій для редагування та видалення
contactsContainer.addEventListener("click", (e) => {
    const delBtn = e.target.closest(".btn-del");
    const editBtn = e.target.closest(".btn-edit");

    if (delBtn) {
        const id = delBtn.closest(".contact-card").dataset.id;
        const contact = manager.getById(id);
        if (contact && confirm(`Видалити контакт "${contact.name}"?`)) {
            manager.remove(id);
            render();
        }
    }
    // Логіка відкриття модального вікна редагування
});
```

## 5. ВІДПОВІДІ НА КОНТРОЛЬНІ ЗАПИТАННЯ

**1. Які семантичні теги HTML5 ви використали у розмітці сторінки та яке смислове навантаження несе кожен із них?**  
Використано: `<header>` (шапка сторінки з назвою та кнопкою теми), `<main>` (основний зміст сторінки), `<section>` (тематичні блоки форми, панелі фільтрів та списку), `<article>` (картки контактів як незалежні інформаційні блоки), `<form>` (інтерактивна форма введення) та `<footer>` (підвал документа).

**2. У чому полягає відмінність між блоковими та інлайновими елементами HTML?**  
Блокові елементи (`div`, `section`, `p`) займають усю доступну ширину контейнера, починаються з нового рядка та підтримують повну блокову модель (висота, ширина, всі поля `margin` і `padding`). Інлайнові елементи (`span`, `a`) займають лише ширину контенту, розміщуються в рядку та не реагують на вертикальні `margin`.

**3. Якими засобами CSS можна побудувати адаптивний макет інтерфейсу? У чому різниця між Flexbox та Grid Layout?**  
Адаптивність забезпечується відносними одиницями, медіа-запитами, Flexbox та CSS Grid. Flexbox є одновимірним (1D) інструментом для позиціонування вздовж одного напрямку (рядок/колонка), а Grid — двовимірною (2D) системою, що одночасно оперує сіткою рядків і стовпців.

**4. Що таке клас у JavaScript ES6+ і з яких елементів він складається?**  
Клас в ES6+ — це формалізований синтаксис прототипного наслідування. Складається з методу `constructor` (ініціалізація властивостей об'єкта) та методів екземпляра, що описують поведінку.

**5. Чим відрізняється оголошення змінних через let і const? Які типи даних є примітивними в JavaScript?**  
`let` оголошує змінну з блочною областю видимості, яку можна переприсвоювати; `const` оголошує константу, посилання на яку незмінне. Примітиви: `string`, `number`, `bigint`, `boolean`, `undefined`, `symbol`, `null`.

**6. Що таке DOM і за допомогою яких методів здійснюється пошук елементів на сторінці?**  
DOM (Document Object Model) — об'єктне дерево документа в пам'яті браузера. Пошук здійснюється методами `document.getElementById()`, `document.querySelector()` (перший збіг за селектором) та `document.querySelectorAll()` (колекція вузлів).

**7. Які методи DOM використовуються для створення, вставлення та видалення елементів?**  
Створення: `document.createElement(tagName)`. Вставлення: `append()`, `appendChild()`. Видалення: `element.remove()`.

**8. Яка різниця між властивостями innerHTML, textContent та value при роботі з елементами сторінки?**  
`textContent` читає/записує чистий текст (безпечний від XSS), `innerHTML` інтерпретує рядок як HTML-розмітку, а `value` зберігає поточне значення полів форм (`input`, `select`, `textarea`).

**9. Як працюють події у JavaScript і чим відрізняється підхід addEventListener() від прямого призначення (onclick)?**  
Події виникають при діях користувача та проходять фази занурення й спливання. Метод `addEventListener()` дозволяє призначати декілька незалежних обробників на одну подію та керувати фазами, тоді як `onclick` перезаписує єдиний призначений обробник.

**10. Що таке делегування подій, на якому механізмі воно ґрунтується та які переваги дає?**  
Делегування подій полягає у встановленні одного обробника на батьківський контейнер замість кожного дочірнього елемента. Ґрунтується на спливанні подій (Event Bubbling). Забезпечує коректну роботу з динамічно створеними елементами та економить пам'ять.

**11. Як обробляється подія відправлення форми (submit) і навіщо викликається event.preventDefault()?**  
Подія `submit` за замовчуванням надсилає дані на сервер із перезавантаженням сторінки. Метод `event.preventDefault()` зупиняє цю поведінку для виконання валідації та оновлення DOM засобами JavaScript без перезавантаження.

**12. Що таке регулярний вираз, як він створюється в JavaScript і які методи застосовуються?**  
Регулярний вираз — об'єкт шаблону для пошуку й валідації тексту. Створюється через літерал `/.../` або `new RegExp()`. Основні методи: `regex.test(str)` (перевірка відповідності), `str.match(regex)`, `str.replace(regex)`.

**13. Які атрибути валідації форм HTML5 ви використали і як вони співвідносяться з валідацією JavaScript?**  
Використано `required`, `placeholder`, `type="tel"`, `type="email"` та атрибут `novalidate`, який відключає стандартні браузерні повідомлення, передаючи повний контроль гнучкій валідації скриптом JavaScript.

**14. Як здійснюється збереження та зчитування даних через localStorage?**  
Дані зберігаються у вигляді рядка. Серіалізація: `localStorage.setItem(key, JSON.stringify(data))`. Зчитування та десеріалізація: `JSON.parse(localStorage.getItem(key))`.

**15. Які обмеження має клієнтська валідація і чому вона не може повністю замінити серверну?**  
Клієнтський код легко вимкнути або обійти в консолі браузера. Клієнтська валідація створює зручний інтерфейс для користувача, тоді як серверна валідація є обов'язковим рівнем безпеки та цілісності бази даних.

Побудовано семантичну структуру сторінки та створено адаптивний інтерфейс на базі технологій CSS3 Grid Layout і Flexbox, що забезпечує коректне відображення компонентів на пристроях із різною шириною екрана. На практиці було опановано використання регулярних виразів (RegExp) для надійної клієнтської валідації обов'язкових і опціональних полів форми з відповідною візуальною індикацією стану помилки. Організовано ефективну обробку користувацьких подій над динамічно створеними елементами DOM-дерева за допомогою патерну делегування подій (Event Delegation), що усунуло потребу створення надлишкових слухачів та попередило можливі витоки пам'яті. Забезпечено збереження стану колекції контактів і обраної теми оформлення (світла/темна) у клієнтському сховищі localStorage у форматі JSON.
