## 1. МЕТА РОБОТИ
Закріплення практичних навичок семантичної верстки веб-сторінок засобами HTML5, формування вмінь створення адаптивних макетів інтерфейсу за допомогою технологій CSS3 (Flexbox та Grid Layout), отримання базових навичок об'єктно-орієнтованого програмування мовою JavaScript ES6+ (створення класів, моделювання сутностей предметної області та реалізація логіки управління колекцією об'єктів), а також набуття практичних навичок динамічної модифікації вмісту сторінки засобами DOM та обробки подій користувача.

   - **За категорією:** формує окремі блоки за категоріями («Родина», «Робота», «Друзі») із картками, впорядкованими за ім'ям;

6. Видалення записів через **делегування подій** із підтвердженням дії користувача.
7. Збереження стану в `localStorage` у форматі JSON.

### 2.2. Додаткове завдання — Варіант 2: «Теми оформлення (Light / Dark mode)»
Реалізовано перемикання між світлою та темною темами за допомогою CSS-змінних (custom properties) та атрибута `data-theme` на кореневому елементі `<html>`. Обрана користувачем тема зберігається в `localStorage` та автоматично застосовується під час наступного відкриття чи оновлення сторінки.

## 4. ОПИС РЕАЛІЗАЦІЇ ТА КЛЮЧОВІ ФРАГМЕНТИ КОДУ

### 4.1. Моделі даних ES6+ (`Contact` та `ContactManager`)
У коді реалізовано рівно два класи відповідно до вимог варіанта 10:

```javascript
class Contact {
    constructor(id, name, phone, email = "", category = "Родина", notes = "", createdAt = new Date().toISOString()) {
        this.id = id || String(Date.now());
        this.name = name.trim();
        this.phone = phone.trim();
        this.email = email.trim();
        this.category = category;
        this.notes = notes.trim();
        this.createdAt = createdAt;
    }
}
```

Клас `ContactManager` містить масив `this.contacts` і реалізує методи:
- `add(data)` — створення та додавання нового контакту;
- `update(id, data)` — оновлення існуючого контакту за `id`;
- `remove(id)` — видалення контакту з колекції;
- `getById(id)` — пошук контакту за унікальним ідентифікатором;
- `search(query, list)` — фільтрація списку за підрядком в імені або номері телефону;
- `filter(category, list)` — фільтрація за категорією;
- `sort(by, list)` — сортування за допомогою `localeCompare` для правильного українського алфавіту;
- `groupBy(list)` — розподіл контактів на окремі підмасиви за категоріями;
- `save()` та `load()` — серіалізація та зчитування даних із `localStorage` через JSON.

### 4.2. Клієнтська валідація та регулярні вирази
```javascript
const nameRegex = /^[a-zA-Zа-яА-ЯіІїЇєЄґҐ\s'-]{2,50}$/;
const phoneRegex = /^(\+?380|0)\d{9}$/;
const emailRegex = /^[^\s@]+@[^\s@]+\.[^\s@]+$/;
```
1. **Ім'я (`nameRegex`):** дозволяє як одне слово («Тарас»), так і декілька слів («Шевченко Тарас Григорович»). Дозволяє літери українського та латинського алфавіту, пробіли, дефіси та апострофи. Довжина від 2 до 50 символів.
2. **Телефон (`phoneRegex`):** перевіряє формат українських номерів (`+380XXXXXXXXX` або `0XXXXXXXXX`).
3. **Email (`emailRegex`):** поле є опціональним. Якщо користувач залишив поле порожнім — помилка не генерується. Якщо ввів дані — виконується перевірка наявності `@` та доменного імені.

### 4.3. Динамічне формування списку (DOM) та групування
Функція `render()` формує дерево елементів:
- Очищує контейнер: `contactsContainer.innerHTML = ""`.
- Отримує відсортовані та відфільтровані контакти, групує їх методом `manager.groupBy(list)`.
- Для кожної категорії з ненульовою кількістю записів створює блок `.category-block` із заголовком та сіткою карток `.contacts-grid`.
- Для кожного контакту створює елемент `article.contact-card` із атрибутом `data-id`, де розміщуються дані та кнопки керування.

### 4.4. Делегування подій для редагування та видалення
Замість навішування обробників на кожну створену кнопку, використовується один обробник на контейнері `contactsContainer`:
```javascript
contactsContainer.addEventListener("click", (e) => {
    const delBtn = e.target.closest(".btn-del");
    const editBtn = e.target.closest(".btn-edit");

    if (delBtn) {
        const id = delBtn.closest(".contact-card").dataset.id;
        const contact = manager.getById(id);
        if (contact && confirm(`Видалити контакт "${contact.name}"?`)) {
            manager.remove(id);
            render();
        }
    }
    // ... логіка відкриття модального вікна редагування
});
```

## 5. ПОКРОКОВИЙ ПЛАН ТА ІНСТРУКЦІЯ ДЛЯ СТУДЕНТА

### Крок 1. Запуск
Відкрийте файл `index.html` у браузері подвійним кліком миші.

### Крок 2. Тестування сценаріїв для захисту та скріншотів:
1. **Помилки валідації:**
   - Натисніть кнопку «Додати контакт» із порожніми полями — поля підсвітяться червоним, з'являться тексти помилок.
   - Введіть некоректний номер телефону (наприклад, `123`) — переконайтеся, що відображається підказка про формат `+380...`.
2. **Коректне додавання:**
   - Введіть ім'я з одного слова («Андрій») або двох слів («Андрій Коваль»).
   - Введіть коректний телефон (`+380991112233`).
   - Поле Email залиште порожнім (або введіть коректний) — форма успішно відправиться, контакт з'явиться у відповідній групі категорій.
3. **Пошук та фільтрація в реальному часі:**
   - Введіть будь-яку літеру або цифри телефону в рядок пошуку — список миттєво відфільтрується.
   - Змініть фільтр категорії на «Робота» або «Друзі».
4. **Редагування:**
   - Натисніть кнопку «Редагувати» на будь-якій картці — відкриється модальне вікно.
   - Змініть номер телефону або нотатки та натисніть «Зберегти» (або закрийте модалку клавішею `Escape` чи кліком повз вікно).
5. **Видалення:**
   - Натисніть «Видалити» — браузер запитає підтвердження. Натисніть «ОК» — контакт видалиться з перерендерингом списку.
6. **Зміна теми та LocalStorage:**
   - Натисніть кнопку «Тема» у шапці — інтерфейс миттєво перейде в темний режим.
   - Натисніть `F12` -> вкладка **Application** -> **Local Storage** — переконайтеся, що там зберігаються ключі `contacts_list` та `app_theme`.
   - Оновіть сторінку (`F5`) — контакти та тема залишаються незмінними.

## 6. ВІДПОВІДІ НА КОНТРОЛЬНІ ЗАПИТАННЯ (п. 1.7 МЕТОДИЧКИ)

1. **Які семантичні теги HTML5 використано?**  
   `<header>`, `<main>`, `<section>`, `<article>`, `<form>`, `<footer>`. Вони структурують документ за змістом, покращують доступність (a11y) та індексацію сторінки браузерами.
2. **Відмінність між блоковими та інлайновими елементами?**  
   Блокові елементи (`div`, `section`, `p`) займають всю ширину рядка і починаються з нового рядка. Інлайнові (`span`, `a`) займають лише ширину свого контенту і не підтримують вертикальні відступи `margin`.
3. **Адаптивний макет: Flexbox проти Grid?**  
   Flexbox — одновимірний (1D, вздовж рядка або колонки, зручно для панелей і кнопок). Grid — двовимірний (2D, одночасно по рядках і колонках, зручно для сіток карток).
4. **Що таке клас у JavaScript ES6+?**  
   Синтаксична обгортка над прототипним наслідуванням. Складається з `constructor` (ініціалізація полів об'єкта) та методів.
5. **Різниця let та const? Примітивні типи?**  
   `let` дозволяє переприсвоювати значення змінної, `const` фіксує посилання. Примітиви: `string`, `number`, `boolean`, `null`, `undefined`, `symbol`, `bigint`.
6. **Що таке DOM та як шукати елементи?**  
   Document Object Model — об'єктне деревоподібне представлення HTML-документа. Пошук здійснюється методами `document.getElementById()`, `document.querySelector()`, `document.querySelectorAll()`.
7. **Методи створення, вставлення та видалення DOM-елементів?**  
   Створення: `document.createElement()`. Вставлення: `appendChild()`, `append()`. Видалення: `element.remove()`.
8. **Різниця innerHTML, textContent та value?**  
   `textContent` записує/читає чистий текст (безпечний від XSS). `innerHTML` парсить текст як HTML-розмітку. `value` зберігає поточне значення поля введення форми (`<input>`, `<select>`).
9. **Як працюють події та навіщо addEventListener()?**  
   Метод `addEventListener()` дозволяє призначати кілька незалежних обробників на одну подію, керувати фазами перехоплення/спливання та безпечно відписуватися.
10. **Що таке делегування подій?**  
    Встановлення одного обробника на батьківський контейнер замість десятків обробників на кожну дочірню кнопку. Ґрунтується на спливанні подій (Event Bubbling) та перевірці `event.target.closest()`.
11. **Навіщо викликається event.preventDefault() у submit?**  
    Щоб скасувати стандартне перезавантаження сторінки браузером та обробити форму локально через JavaScript.
12. **Що таке регулярний вираз та методи роботи з ним?**  
    Об'єкт шаблону для пошуку й валідації тексту. Створюється через літерал `/.../` або `new RegExp()`. Методи: `test()`, `exec()`, `match()`, `replace()`.
13. **Атрибути валідації HTML5 та їх зв'язок з JS?**  
    Атрибут `novalidate` на формі вимикає стандартні повідомлення браузера, передаючи повний контроль гнучкій клієнтській валідації через JavaScript.
14. **Збереження та зчитування через localStorage?**  
    `localStorage.setItem(key, JSON.stringify(data))` — серіалізація об'єктів у рядок. `JSON.parse(localStorage.getItem(key))` — десеріалізація назад в об'єкти.
15. **Обмеження клієнтської валідації?**  
    Клієнтський код можна вимкнути або обійти в консолі браузера. Тому клієнтська перевірка потрібна для зручності користувача (UX), а серверна — для безпеки та цілісності даних.
